Purpose

Implement issue #7 with automatically selected design guidance, locally searchable visual material, an unobtrusive working state, and honest verification evidence.

Problem

The host disables skills, its bounded workspace reader cannot access personal guidance, and chat renders thinking/tool execution details. Personal skills are manual-only and have no declared redistribution license. Descriptions alone do not prove loaded guidance. The existing catalog already provides reviewed desktop/mobile pairs, tags, cues and hashes.

Solution

Use explicit, consented local Markdown imports, pi's native skill parser and resource overrides, and app-owned normalized copies. Never mutate terminal configuration or ship personal content. Classify common requests before dispatch and attach complete selected skill content; provide a bounded resource-read tool for model-driven refinement and supporting Markdown. Search the catalog by request, family, style and viewport; return verified local image bytes to image-capable models, metadata-only otherwise. Keep provenance, enablement and diagnostics in the existing temporary settings sheet, not the transcript. Preserve approvals, errors, stop and change review.

The founder approved apple-design (UI), mobile-native (responsive), emil-design-eng (motion/polish), prototype (variants) as local-only imports. Apple guidance must not impose its visual style on target projects. Executable extensions and package imports remain explicitly unsupported; missing tools must produce actionable errors, never silent approval or installation.
